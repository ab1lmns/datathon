# Forte — видеоаналитика кассовых операций

Forte — веб-приложение для проверки видеозаписей кассовых операций, подготовленное для Datathon 26. Пользователь загружает MOV-видео, система анализирует его на GPU и возвращает найденные события с таймкодами, кадрами и связанными нормативными источниками Республики Казахстан.

Проект помогает проверяющему перейти от длинной записи к конкретному моменту и проверить основание вывода. Результат модели — материал для проверки человеком, а не окончательное юридическое заключение.

## Что умеет приложение

- **Обзор:** состояние проверок и события, требующие внимания.
- **Видеоотчёты:** загрузка записи, ожидание обработки, просмотр результатов, событий и кадров.
- **Просмотр видео:** переход к таймкоду, изменение скорости, перемотка и повтор фрагмента вокруг события при доступном исходном видео.
- **Нормативные источники:** каталог из 12 документов и 72 тем, поиск по номеру, названию и содержимому, ссылки на конкретные пункты официальных текстов.
- **Подключение:** настройка адреса API, ввод ключа и проверка доступности сервера.

Каталог источников доступен независимо от загруженных отчётов. Он построен из локального нормативного пакета; дата проверки пакета не означает автоматической проверки актуальности законодательства на сегодняшний день.

## Как устроена обработка

```text
Браузер: React + TypeScript
          │ MOV / X-API-Key
          ▼
Gateway: FastAPI — интерфейс, Swagger, проксирование API
          │
          ▼
GPU API: FastAPI → очередь → один GPU worker
                              │
                              ▼
                    анализ кадров и событий
                              │
                              ▼
                 JSON, таймкоды и JPEG-кадры
          │
          ▼
Gateway добавляет нормативные ссылки и условия применимости
          │
          ▼
Видеоотчёт в браузере
```

**Frontend:** React 19, TypeScript, Vite, Lucide, Three.js для визуальных компонентов.

**Backend:** Python 3.12, FastAPI, Uvicorn, FFmpeg/FFprobe и локальный движок `forte`. Gateway работает отдельно от GPU API и не загружает модели.

**Модели:** RT-DETR v2 для людей и предметов, OWLv2 для поиска объектов по категориям, DINOv2 для визуальных признаков, локальные классификаторы сейфа, денег и папки, Qwen3-VL-4B для отдельных вопросов по двери и экрану. Точные версии и ссылки на веса — в [реестре моделей](backend/DEPLOYED_MODELS.md).

После установки зависимостей и загрузки весов анализ выполняется локально, без внешних AI API. Нормативное обогащение использует локальный справочник. Qwen не выбирает нормативную статью автоматически в рабочей версии.

## Быстрый старт: готовый сервис

1. Откройте [приложение](https://forte.makquiz.site:14901).
2. Перейдите в «Подключение» и введите выданный API-ключ. Адрес API оставьте пустым: запросы пойдут на тот же сайт.
3. Проверьте готовность сервера. `worker: ready` в Health означает, что модели загружены; `loading` — загрузка ещё идёт.
4. Загрузите непустой файл `.mov` размером до **200 MiB**.
5. Дождитесь результата и откройте событие в видеоотчёте.
6. При необходимости откройте связанное правило и официальный источник.

В Swagger откройте окно авторизации и укажите тот же ключ. Для загрузки используется `POST /api/v1/analyze`, затем результат запрашивается по полученному `job_id`.

## Локальный запуск

Все команды ниже, кроме явно обозначенных переходов `cd`, выполняются из корня репозитория. Нужны Git, Node.js с npm (рекомендуется Node.js 22.18+ для запуска тестов с `--experimental-strip-types`) и Python 3.12. GPU нужен только для полного запуска анализа.

```bash
git clone https://github.com/ab1lmns/datathon.git
cd datathon
npm ci --prefix frontend
```

### Вариант 1. Интерфейс с удалённым GPU-сервером

Подходит для разработки интерфейса на Mac или компьютере без NVIDIA GPU. Модели остаются на сервере.

**Терминал 1 — локальный gateway:**

```bash
cd backend
python3.12 -m venv .venv-web
source .venv-web/bin/activate
pip install -r requirements-web.txt
FORTE_API_UPSTREAM=https://forte.makquiz.site:14901 \
  python -m uvicorn service.gateway:app --host 127.0.0.1 --port 8080
```

**Терминал 2 — frontend, из корня репозитория:**

```bash
npm run dev --prefix frontend
```

Откройте адрес, напечатанный Vite, обычно [http://127.0.0.1:5173](http://127.0.0.1:5173). В разделе подключения оставьте API URL пустым и введите ключ удалённого сервера. Vite направляет `/api` на локальный gateway по порту 8080.

Локальный Swagger доступен по адресу [http://127.0.0.1:8080/docs](http://127.0.0.1:8080/docs). Он использует API выбранного upstream. Удалённый сервис должен быть доступен; локальный запуск интерфейса не заменяет сервер анализа.

Если нужен только просмотр интерфейса, достаточно команды Vite. Анализ видео без доступного API работать не будет.

### Вариант 2. Полный запуск на своём GPU

Требования: Linux, Python 3.12, NVIDIA GPU с 24 GB VRAM, совместимый драйвер, FFmpeg и FFprobe. Установка на совершенно новой машине отдельно не подтверждена; зафиксированные зависимости и процедура переноса приведены в [backend/README.md](backend/README.md).

**1. Установите backend и задайте окружение:**

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-service.txt
cp .env.example .env
```

Отредактируйте `.env`: задайте собственный `FORTE_API_KEY`, существующий каталог весов `HF_HOME` и каталог данных `FORTE_DATA_DIR`. Затем загрузите переменные в текущий терминал:

```bash
set -a
source .env
set +a
```

`.env` автоматически приложением не читается.

**2. Однократно скачайте веса**, если их ещё нет в `HF_HOME` (потребуются интернет и место для больших файлов):

```bash
HF_HUB_OFFLINE=0 python scripts/download_models.py
```

**3. Запустите GPU API:**

```bash
export HF_HUB_OFFLINE=1
python scripts/verify_source.py
python -m uvicorn service.app:app --host 127.0.0.1 --port 8000 --workers 1
```

Используйте один worker, без `--reload`: несколько процессов могут загрузить несколько копий моделей. Дождитесь готовности в [Health GPU API](http://127.0.0.1:8000/api/v1/health).

**4. В другом терминале соберите frontend из корня проекта:**

```bash
npm ci --prefix frontend
npm run build --prefix frontend
```

**5. Запустите gateway:**

```bash
cd backend
source .venv/bin/activate
FORTE_API_UPSTREAM=http://127.0.0.1:8000 \
  python -m uvicorn service.gateway:app --host 127.0.0.1 --port 8080
```

Готово: [приложение](http://127.0.0.1:8080), [Swagger](http://127.0.0.1:8080/docs), [Health](http://127.0.0.1:8080/api/v1/health). В интерфейсе введите ключ, заданный для GPU API.

Для внешнего доступа используйте TLS reverse proxy перед gateway. Внутренний GPU API напрямую публиковать не следует: он содержит старые маршруты `/ui` для совместимости.

### Доступ команды через SSH

Если у вас есть SSH-ключ и доступ к текущему серверу, можно использовать туннель вместо публичного HTTPS:

```bash
ssh -N -i ~/.ssh/fortebank_vast -p 14814 \
  -L 17860:127.0.0.1:7860 root@95.3.33.46
```

Приложение будет доступно по [http://127.0.0.1:17860](http://127.0.0.1:17860), Swagger — по [http://127.0.0.1:17860/docs](http://127.0.0.1:17860/docs). Для локальной разработки укажите gateway `FORTE_API_UPSTREAM=http://127.0.0.1:17860`. Этот способ требует доступа команды и не является публичной ссылкой для жюри.

## Настройки

Примеры: [backend/.env.example](backend/.env.example) и [frontend/.env.example](frontend/.env.example).

| Переменная | Назначение / значение из примера |
|---|---|
| `FORTE_API_KEY` | Ключ доступа к анализу и результатам; задайте собственный |
| `FORTE_API_UPSTREAM` | Адрес GPU API или удалённого gateway; локально `http://127.0.0.1:8000` |
| `FORTE_DATA_DIR` | Каталог заданий и результатов; `./data/service` |
| `FORTE_JOB_TIMEOUT` | Бюджет задачи, включая приём и очередь; `285` секунд |
| `FORTE_MAX_ACTIVE_JOBS` | Максимум незавершённых задач; `2` |
| `FORTE_MAX_UPLOAD_MB` | Лимит файла; `200` MiB |
| `FORTE_KEEP_API_VIDEOS` | `0` — удалять исходные API-видео после обработки |
| `HF_HOME` | Каталог локальных весов Hugging Face |
| `HF_HUB_OFFLINE` | `1` — использовать локальные веса без скачивания |
| `FORTE_FRONTEND_DIST` | Необязательный путь к сборке frontend; по умолчанию `frontend/dist` |
| `VITE_API_BASE_URL` | Пустое значение — API на том же origin; при разработке работает прокси Vite |

Не помещайте ключи в `VITE_*`: эти значения попадают в клиентскую сборку. Не коммитьте `.env` и не передавайте API-ключ в URL.

## API и примеры запросов

| Метод | Маршрут | Назначение | API-ключ |
|---|---|---|---|
| `POST` | `/api/v1/analyze` | Multipart-поле `file` с MOV; возвращает `job_id` | Да |
| `GET` | `/api/v1/jobs/{job_id}` | Состояние и результат задания | Да |
| `GET` | `/api/v1/health` | Готовность worker и состояние очереди | Нет |
| `GET` | `/docs` | Swagger UI | Нет для страницы |
| `GET` | `/openapi.json` | Машиночитаемая схема API | Нет |

Пример для Bash; замените путь к видео и введите выданный ключ:

```bash
export BASE_URL='https://forte.makquiz.site:14901'
read -r -s -p 'API key: ' API_KEY
export API_KEY

curl --fail-with-body "$BASE_URL/api/v1/health"

curl --fail-with-body -X POST "$BASE_URL/api/v1/analyze" \
  -H "X-API-Key: $API_KEY" \
  -F 'file=@/absolute/path/to/example.mov'
```

Ответ загрузки: `{"job_id":"..."}`. Подставьте полученный ID и опрашивайте результат примерно раз в две секунды:

```bash
export JOB_ID='ID_ИЗ_ОТВЕТА'
curl --fail-with-body "$BASE_URL/api/v1/jobs/$JOB_ID" \
  -H "X-API-Key: $API_KEY"
```

Состояния: `processing` — обработка, `done` — готово, `failed` — ошибка. Готовый ответ содержит `verdict`, список `violations`, таймкоды `timecode_sec`, JPEG-кадры `evidence_frames` и при наличии нормативное основание `rule`.

`no_violation` означает, что система не нашла признаки поддерживаемых событий. Это не доказательство отсутствия всех возможных нарушений. Ошибка `failed` также не является отрицательным результатом.

Подробная структура JSON, нормативные поля и коды ответов: [docs/API.md](docs/API.md).

## Данные и ограничения

- Исходные API-видео по умолчанию удаляются после обработки. Кадры и результаты остаются на сервере и доступны по `job_id` с API-ключом.
- История отчётов интерфейса хранится в памяти текущей вкладки и сбрасывается при перезагрузке. Серверный результат по сохранённому ID остаётся доступен.
- Очередь последовательная. По умолчанию принимаются не более двух незавершённых задач; при заполнении сервер отвечает `429`.
- Бюджет серверной задачи — 285 секунд; ожидание UI — 300 секунд. Отмена ожидания в браузере не отменяет серверную задачу. Успешная обработка за пять минут при произвольной нагрузке не гарантируется.
- Обучающие видео, большие базовые веса, секреты и экспериментальные адаптеры не входят в репозиторий.

### Какие события ищет рабочая версия

| Сценарий | Ограничение интерпретации |
|---|---|
| Предметы или ценности без присмотра | Содержимое сумки или папки не всегда видно |
| Открытый сейф | Юридическая применимость зависит от условий |
| Наличные на столе при следующем посетителе | Возможны ошибки распознавания объектов и момента |
| Дополнительный человек / человек за кассиром | Полномочия человека по видео неизвестны |
| Передача сумки и уход передающего | Отсутствие проверки не всегда доказуемо |
| Личные предметы / питьё | Требуется проверка контекста |
| Открытая дверь при работе | Связанная норма не доказывает нарушение сама по себе |
| Признаки незаблокированного рабочего места | Прямое нормативное основание не установлено |

Отсутствие проверки подлинности, отсутствие идентификации и пересчёт без клиента не включены в рабочий поиск.

Рабочая сборка от 18.10.2026 получила **17/21 положительных видео и 0/19 ложных срабатываний на отрицательных** в полном прогоне 40 знакомых видео. Включены обученная голова папки и визуальная проверка ошибочно подавленных треков людей; экспериментальные LoRA не используются. Это бинарная метрика, а не 17 безошибочных причин, таймкодов и нормативных квалификаций; перенос на новые ракурсы не проверен. В интерфейсе показываются реальные ответы сервера, без подстановки по имени файла. [Проверки и состав обновления](docs/OBSERVATIONS_RELEASE_20261018.md).

## Проверки и обновление каталога

Из корня репозитория:

```bash
npm test --prefix frontend
npm run build --prefix frontend
```

Backend — в активированном Python-окружении с установленными зависимостями:

```bash
cd backend
python -m unittest discover -s tests -v
python scripts/verify_source.py
```

После изменения нормативных данных пересоздайте каталог из корня проекта:

```bash
node frontend/scripts/build-sources-catalog.mjs
npm test --prefix frontend
npm run build --prefix frontend
```

`verify_source.py` проверяет соответствие зафиксированному серверному снимку; после осознанных изменений исходников расхождение с манифестом требует отдельной проверки.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `401` | Ключ указан и совпадает с ключом сервера |
| `400` / `413` | Файл непустой, имеет формат MOV и укладывается в лимит |
| `429` | Очередь заполнена; повторите запрос позже (`Retry-After: 30`) |
| `503` | Доступен ли upstream и запущен ли GPU API |
| `worker: loading` | Дождитесь загрузки моделей |
| Задание завершилось `failed` | Прочитайте поле `error`; проверьте видео и логи GPU API |
| Vite открыт, анализ недоступен | Gateway запущен на 8080, upstream доступен, ключ введён |
| Gateway не показывает интерфейс | Выполните сборку frontend, проверьте `FORTE_FRONTEND_DIST` |
| После изменения интерфейса видна старая версия | Пересоберите frontend и обновите страницу |

### Просмотр записи и доказательств

Плеер загруженного видео поддерживает метки событий, скорость 0,25–2×, перемотку ±1 с, повтор ±3 с вокруг события и сохранение JPEG текущего кадра. В кадрах анализа можно выбрать объект и посмотреть доступную историю наблюдений. Нормативное основание и официальные ссылки открываются прямо в отчёте.

Датасет и демонстрационные ролики не входят в публичную сборку. Для проверки загрузите своё видео и подключите API. Старые отчёты без координат продолжают отображаться; выбор объектов появляется после нового анализа обновлённым backend. Подробнее: [объекты на кадре](docs/OBJECT_INSPECTOR.md).
