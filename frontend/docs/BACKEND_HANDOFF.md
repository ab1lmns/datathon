# Передача фронтенда команде backend / AI

Фронтенд готов к контракту Datathon 26. Базовый FastAPI-сервер теперь находится в `../../backend/`; запуск описан в `../../backend/README.md`. Модель анализа пока не подключена. Контракт фронтенда: `src/api/types.ts`, `src/api/client.ts`, `src/hooks/useReviews.ts`.

## Быстрое подключение

1. Запустите ваш API, например на `http://127.0.0.1:8000`.
2. Запустите фронтенд: `cd frontend && npm ci && npm run dev`.
3. Откройте страницу «Подключение». Выберите API, введите базовый адрес **без /api/v1**, затем ключ. При пустом адресе запросы идут на текущий origin.
4. Загрузите MOV. Запросы уже реализованы, интерфейс переписывать не нужно.
5. Для базового адреса по умолчанию можно скопировать `.env.example` в `.env.local`, затем перезапустить Vite. Режим всё равно выбирается явно в UI.

Настройки и ключ находятся только в памяти, после обновления вкладки сбрасываются. API-ключ не встраивается в JS, localStorage или URL. Примерные проверки скрываются в режиме API. Запись не подменяется демо-результатом при сбое сервера.

## Обязательный контракт из ТЗ

`POST /api/v1/analyze`
- multipart/form-data, поле **file**, исходный файл `.mov`.
- Заголовок `X-API-Key: <key>`, если ключ задан.
- Content-Type не задаётся вручную: браузер добавляет boundary.
- Ответ 200 или 202: `{ "job_id": "unique-id" }`.

`GET /api/v1/jobs/{job_id}` с тем же заголовком.

В процессе:
```json
{ "job_id": "unique-id", "status": "processing" }
```
Готовый результат:
```json
{
  "job_id": "unique-id",
  "status": "done",
  "verdict": "violation",
  "violations": [{
    "type": "Тип наблюдаемого события",
    "timecode_sec": 9.0,
    "description": "Наблюдаемое действие и обоснование возможного нарушения",
    "evidence_frames": [{ "timestamp_sec": 9.0, "image_base64": "<JPEG base64 без префикса>" }]
  }]
}
```
Без событий: `status: done`, `verdict: no_violation`, `violations: []`.
Ошибка: `{ "job_id": "unique-id", "status": "failed", "error": "Понятное объяснение" }`.

`error` — согласованное расширение для UI; ТЗ задаёт только статус `failed`. Без сообщения выводится общий текст. HTTP 401/403, 413, 415, 422, 429 и 5xx тоже обрабатываются. Возвращайте JSON, а не HTML.

В одном результате может быть несколько событий; у каждого — 1–3 кадра JPEG. Фронтенд проверяет форму ответа, неотрицательные конечные таймкоды и согласованность вердикта со списком. Некорректный ответ становится ошибкой, а не успешной проверкой. Отсутствие обязательных кадров считается некорректным ответом. Неподдерживаемый браузером кодек исходного MOV не препятствует отображению кадров API.

## Необязательные расширения (не входят в JSON-пример ТЗ)

`progress: number` 0–100 у processing. Если отсутствует, показывается «Обработка…», без выдуманного процента.

Для требования ТЗ о нормативном источнике добавьте **к каждому нарушению**:
```json
"rule": {
  "document": "Проверенное название нормативного акта РК",
  "section": "Пункт / раздел",
  "url": "https://adilet.zan.kz/..."
}
```
UI уже выводит название, пункт и ссылку в окне правила и на странице нормативной базы. Без поля показывает «источник не предоставлен». Поле необязательно для совместимости с минимальным API жюри, но нормативное обоснование требуется продуктовым сценарием ТЗ. Не выдумывайте источники. Разрешены только HTTP(S)-ссылки.

## Ожидание и отмена

Первый GET выполняется сразу после POST, затем каждые 2 секунды, без перекрытия запросов. Общий лимит — 300 секунд с начала загрузки, включая сеть. AbortController отменяет текущий запрос/опрос по таймауту, кнопке отмены и размонтированию. Клиентская отмена **не отменяет вычисления на сервере**: endpoint отмены в ТЗ отсутствует. «Повторить» заново отправляет сохранённый File и создаёт новую задачу. Обработка не продолжается автоматически после перезагрузки страницы; история не обязательна по ТЗ.

## Сеть / развёртывание

- При разных origin разрешите CORS для адреса фронтенда (dev: `http://127.0.0.1:5173`, при необходимости `http://localhost:5173`), методы POST/GET/OPTIONS, заголовки X-API-Key и Content-Type.
- Для production предпочтителен reverse proxy: `/api/v1/*` → FastAPI, остальное → `frontend/dist/`. Vite dev-server проксирует `/api` и `/health` на `http://127.0.0.1:8000`.
- HTTPS-фронтенд должен обращаться к HTTPS API; иначе браузер блокирует mixed content.
- Ключ жюри выдаёт backend. Пользовательский ключ доступен владельцу вкладки; секреты сервера не включать в VITE_*.
- AI работает на сервере команды локально, без внешних AI API. Фронтенд отправляет видео только на явно настроенный адрес.
- MOV обязателен. Клиентский предел 250 МБ — выбранный запас над ~29 МБ из ТЗ, не лимит самого ТЗ. Согласуйте с лимитом прокси/сервера.

## Датасет и демо

Архив содержит 42 MOV и `open_labels.xlsx`, столбцы: файл, таймстемп, нарушение / без нарушения. Типы событий и нормативные источники в разметке отсутствуют. Имена используют латинскую X и кириллическую Х; не нормализуйте молча на сервере.

Использованы только три локальных примера:
- Х-26 → нарушение, 9 секунд;
- Х-3 → без нарушения;
- Х-20 → нарушение, **5 секунд**.

UI не присваивает им придуманные типы. Эти записи обозначены как примеры из разметки, не как результат AI. При загрузке произвольного видео в демо показывается процесс, затем сообщение о необходимости API, без фиктивного вердикта. Настоящий API должен анализировать содержимое, а не сверять имя с разметкой.

Видео `public/demo/*.mov` исключены из Git. Не публикуйте датасет. При production-сборке Vite копирует public в dist, поэтому перед публичным развёртыванием исключите локальные демо-видео из public и пересоберите приложение. Для пустого public предусмотрена заглушка отсутствующего превью.

## Проверки перед интеграцией

`npm test` (Node 22.6+ с strip-types или Node 24) проверяет multipart-контракт, ключ, идентификатор задачи, валидацию ответа, отмену и HTTP-ошибки. `npm run build` проверяет TypeScript и сборку.

После запуска вашего сервера вручную пройти: MOV → processing → violation с несколькими событиями/кадрами/правилами; no_violation; failed; неверный ключ; таймаут; отмена; повтор; неподдерживаемый кодек. Реальный AI и настоящий backend этими клиентскими тестами не проверяются.

## Обновлённый интерфейс

UI разделён на компоненты: `ReviewDetail.tsx` (результат, события, кадры и плеер), `Modal.tsx` (диалоги с клавиатурной навигацией и мобильными панелями снизу), `ConnectionSettings.tsx` (настройки), `ForteSculpture.tsx` (3D-логотип), `BrandIntro.tsx` (стартовая анимация с пропуском и таймаутом). API-контракт не изменён. Поиск и фильтры синхронизируют выбранную карточку с видимым списком; на телефоне выбор записи прокручивает к результату, кнопка «К проверкам» возвращает к списку.

Golos Text с кириллицей загружается локально через `@fontsource-variable/golos-text` (OFL). Иконки — `lucide-react`. Внешних запросов к Google при запуске нет. SVG логотипа сохранён из публичной шапки https://forte.kz/ (17.10.2026) в `src/assets/forte-logo.svg` и используется как основа экструзии Three.js. Это декоративная интерпретация для интерфейса. Three.js загружается отдельным модулем; модель останавливается вне экрана / в скрытой вкладке, учитывает prefers-reduced-motion, освобождает GPU-ресурсы при размонтировании. Без WebGL остаётся SVG-версия. 3D не связано с обработкой видео.
