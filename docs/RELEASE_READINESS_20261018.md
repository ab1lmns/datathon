# Аудит текущего релиза Forte — 18 октября 2026

## Решение

**Основной сценарий и контракт API реализованы. Переходить исключительно к дообучению пока рано:** остаются надёжность внешней загрузки, общий срок 300 секунд с очередью, переносимость и ограничения обоснований. Не заявляем полное соответствие, независимую точность или гарантированный uptime.

Прочитано исходное `Кейс_ForteBank.docx` целиком, включая FAQ и таблицы. ТЗ не требует 21 определённый класс. 21/19 — количество положительных/отрицательных видео внутреннего набора. Требование FAQ 24 допускает лицензированные open-source компоненты, FAQ 35 запрещает готовые решения; авторство backend уточнено пользователем как командное. Аудит кода не является решением организаторов о допуске.

## Что на Mac и сервере

- Источники распознавания `forte/`, оба файла классификаторов и ресурсы совпадают с GPU deployment по SHA-256.
- Публичный gateway/service/regulatory: **33/33** сравненных файла совпали после синхронизации.
- Frontend src и dist: **40/40** сравненных файла совпали. Раньше на сервере отсутствовал src, сейчас исходники добавлены.
- Полный текущий исходный комплект лежит на сервере в `/workspace/forte_web_release_20261018`, локально — в этой рабочей папке. Большие веса остаются в серверном HF_HOME, а не на Mac/в Git.
- Отдельный действующий GPU-каталог `/workspace/forte_live_20261018` **не идентичен всему локальному backend**: 9 отличий относятся к gateway, нормативному слою, экспериментальному поиску и оформлению docs. Они не загружаются GPU worker. `service/app.py` отличается только заголовком/описанием встроенного FastAPI. Его прежняя версия продолжает работать; GPU не перезапускали ради косметики.
- Данные, секреты, venv и исследовательские артефакты намеренно не зеркалируются. Синхронизация исходников не означает одинаковое окружение Mac/Linux.
- Таблица SHA-256: `evaluations/runtime-parity-20261018.json`; новый локальный манифест `backend/deploy/current-release-sha256.json`. Исторические манифесты сохранены.
- Изменения есть в рабочей папке, в том числе новые ещё не отслеживаемые Git файлы. **Свежий git clone не гарантирует получение этого релиза, пока не создан и не отправлен release commit.** Автоматический push/merge в этом аудите не выполнялся.

## Что сделать до «занимаемся только моделью»

1. Довести внешний транспорт: полный MOV 29 МБ / до 145 с, два последовательных и параллельных запроса через выбранный финальный URL. Успех health/Swagger недостаточен. Cloudflare сейчас имеет успешный контроль; Funnel с Mac не прошёл загрузку.
2. Ограничить приём очереди и учитывать полный дедлайн от принятия задания; проверить восстановление после сбоя. Не обещать 300 секунд при произвольной нагрузке.
3. Выпустить отдельный ключ жюри, передать приватно; текущий ключ уже попадал в переписку. Во время аудита ключ не менялся.
4. Зафиксировать проверенный commit и проверить установку на чистом окружении; сохранить лицензии. Для полностью автономной документации локально поставить Swagger JS/CSS.
5. Определить удаление результатов жюри после хакатона; не включать их в training manifest.
6. После этого обучать в отдельном окружении/окне времени. Сервис сдачи не должен делить GPU с тренировкой. Сравнивать новый адаптер с baseline по типам, FN, FP, PTS, времени и памяти; откатывать регрессию.
