## Главные риски для баллов и допуска

1. **Авторство:** пользователь уточнил, что backend создан его другом для команды.
   Прежнее предположение о заимствованном готовом решении отозвано. Это не меняет
   необходимость указывать авторов и лицензии используемых предобученных компонентов.
2. **Качество:** действующий результат — прежние **15/21 положительных, 0/19 отрицательных**
   на знакомых видео по бинарному verdict. Это не 15 правильных типов/таймкодов и не независимый тест.
   D (проверка подлинности), I (идентификация клиента), J (пересчёт без клиента) в production-поиск
   не включены. Х-34 пропускается. Отключённые сценарии не вызывают падения сервиса, но снижают полноту.
3. **Обоснования:** описание отдельных событий может утверждать содержимое/роль/отсутствующее
   действие без полного подтверждения. Нужна сверка визуальных формулировок и связей с нормами;
   дисклеймер сам по себе не исправляет неподтверждённое утверждение.
4. **Доступность:** quick tunnel временный; нужен постоянный URL либо гарантированное поддержание
   текущего процесса на весь период проверки. Текущий сервер доступен, но это не гарантия uptime.
5. **Время:** FIFO-очередь одного worker может задержать видео более 300 секунд с момента загрузки.
   Нужны ограничение очереди/контроль общего дедлайна и отдельная проверка конкурентной загрузки.
6. **Секреты:** используемый ключ уже попадал в переписку. Перед передачей жюри выпустить отдельный
   ключ и обновить локальный приватный файл/настройки; не публиковать ключ в репозитории.
   Во время аудита ключ не менялся, чтобы не отключить пользователя.
7. **Данные жюри:** исходный API-upload удаляется после обработки по умолчанию; JSON с JPEG
   остаётся в хранилище задач. Нужно определить срок хранения и удаление после хакатона.
   Их нельзя публиковать или использовать для обучения. Аудит использовал только учебные видео.

## Приоритет перед сдачей

- Указать командное авторство backend и лицензии компонентов.
- Зафиксировать постоянный адрес и ключ для жюри, оставить GPU без обучения.
- Закрыть неподтверждённые утверждения в описаниях; завершить нормативную сверку по официальному экспорту.
- Проверить несколько одновременных загрузок и общий 300-секундный дедлайн.
- Пройти UI кликами, зафиксировать release commit и комплект инструкции/ограничений.
- После этого улучшать пропущенные сценарии отдельно с регрессионной проверкой.

Ожидаемый балл не вычислялся: новые видео, ручная оценка причин/кадров и трактовка допуска неизвестны.
Публичный API технически готов принимать задания; заявление «всё соответствует и всё находит» неверно.
