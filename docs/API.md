# API

Базовый адрес — тот же HTTPS-сайт, что и интерфейс. `X-API-Key` обязателен для загрузки и чтения результата. Не передавайте ключ в URL.

```bash
# BASE_URL и API_KEY задаются локально, не сохраняются в Git.
curl --fail-with-body -X POST "$BASE_URL/api/v1/analyze" \
  -H "X-API-Key: $API_KEY" -F 'file=@example.mov'

curl --fail-with-body "$BASE_URL/api/v1/jobs/JOB_ID" \
  -H "X-API-Key: $API_KEY"
```

Первый ответ: `{"job_id":"..."}`. Опрашивайте результат примерно раз в две секунды.

```json
{
  "job_id": "...",
  "status": "done",
  "verdict": "violation",
  "violations": [{
    "type": "Название типа",
    "timecode_sec": 12.5,
    "description": "Наблюдаемое действие и нормативное основание",
    "evidence_frames": [{"timestamp_sec": 12.5, "image_base64": "JPEG_BASE64"}],
    "rule": {"document": "Название документа", "section": "Пункт", "url": "https://adilet.zan.kz/..."}
  }]
}
```

`rule` — дополнительное поле публичного gateway: официальный источник, пункт, цитата и условия применимости. Тип события, verdict, таймкод и JPEG сохраняются. Известные шаблоны описания уточняются, чтобы не утверждать содержимое предметов, полномочия людей и юридическую применимость без доказательств. Исходная запись GPU API остаётся неизменной.

Без нарушения: `verdict: no_violation`, `violations: []`. При обработке: `status: processing`. При ошибке: `status: failed`, `error` с причиной; это не отрицательный результат.

HTTP 429: очередь заполнена, Retry-After: 30; повторить позже. HTTP 408: истёк срок приёма видео. HTTP 401: ключ отсутствует или неверен. 400: пустой файл/не MOV. 413: превышен лимит. 404: задания нет. 503: GPU API недоступен. Файл с MOV-расширением, но испорченным содержимым может быть принят, а затем завершиться `failed`.

`GET /api/v1/health`: `status: ok`, `worker: ready` означает готовность; `loading` — загрузка моделей. Health не проверяет API-ключ. Поле `queue` показывает ожидающие задания, `busy` — работу текущего worker.

На сервере общий бюджет принятой задачи — 285 с от входа запроса в GPU API, включая приём тела и очередь. Просроченная задача получает failed; поздний результат не переопределяет её. Одновременно принимается не более двух незавершённых задач (FORTE_MAX_ACTIVE_JOBS). Это ограничивает перегрузку, но отказ/failed не считается успешной обработкой по ТЗ. Время передачи до серверного приложения и доступность внешнего туннеля этим бюджетом не контролируются.

В UI ожидание ограничено 300 с. Отмена ожидания не отменяет задачу сервера.

Исходные видео удаляются после обработки. Кадры и результаты остаются на сервере и доступны по ID с ключом команды. История UI хранится в памяти текущей вкладки; после перезагрузки список сбрасывается. API-результат по сохранённому `job_id` остаётся доступен.

## Нормативный модуль

Локальный справочник содержит 72 записи. Официальные тексты сохранены в `backend/regulatory/source_evidence`, результат сверки цитат — `source_audit.json`; корректировки пунктов — `applicability_sources.json`. Сверка текста и доказательство условий события — разные проверки.

`rule.sources` — официальные ссылки/пункты/цитаты; `rule.rule_ids` — идентификаторы правил; `rule.unknown_conditions` — невидимые или неподтверждённые условия. `rule.relation` принимает CONDITIONAL_BASIS, RELATED_ONLY или NO_DIRECT_BASIS. `assessment: NEEDS_REVIEW` не является третьим verdict и не скрывает визуальное событие.

Для L прямой нормативный источник не установлен: ссылка не выдумывается. Для B/E/H нормы связанные, а не прямое доказательство нарушения. Автоматический выбор статьи Qwen в production не включён. Подробности: [проверка применимости](REGULATORY_APPLICABILITY_FIX.md).

`/api/v1/jobs/{job_id}/review` — устаревший маршрут; публично закрыт и исключён из Swagger. Результат текущего задания, включая кадры, возвращает обычный `GET /api/v1/jobs/{job_id}`.
