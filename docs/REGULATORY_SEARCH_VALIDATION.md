# Подбор нормативных оснований: проверка 18.10.2026

## Решение

В рабочий интерфейс включены сверенные цитаты и официальные ссылки. Автоматический выбор основания Qwen **не допущен**: фактический тест выявил ошибки понимания условий. Текущая рабочая привязка событий к справочным нормам остаётся явной; она не выдаётся за выбор Qwen.

## Официальные источники

`scripts/audit_regulatory_sources.py` получил 12 документов через публичный API «Әділет» по идентификаторам версий. Авторизация не использовалась. Снимки сохранены в `backend/regulatory/source_evidence`, SHA-256 и результаты сопоставления — в `source_audit.json`.

У всех 72 правил текст предоставленного отрывка найден в официальном документе. Это **проверка текста**, не подтверждение всех 72 правил для любого видео. Отключённые, ручные и ранее непроверенные категории не включаются автоматически. Цитаты некоторых правил — только вводная часть пункта, что также не доказывает конкретный запрет.

При первоначальном получении обнаружены расхождения якорей у CASH_056/057/066. При повторном получении официального документа исходные якоря соответствовали цитатам; итоговый снимок не содержит исправленных якорей. Поэтому первоначальная гипотеза о трёх неверных ссылках не считается установленной. Снимок и хеш сохраняются для воспроизводимости; изменение содержимого внешнего API требует повторной сверки.

Абзацы без HTML-якорей проверяются по уникальному совпадению текста и ведут на официальный документ. В №14 есть временные редакции до 01.01.2027 — совпадение цитаты не отменяет необходимость учитывать дату события. Значение `is_actual` источника не равнозначно юридическому заключению о применимости на произвольную дату.

## Реализованный поиск

`service/regulatory_search.py`:

- Поиск среди разрешённых правил по тексту наблюдений, без таблицы соответствия кодов событий и пунктов.
- Qwen получает найденные положения, условия и наблюдения с идентификаторами и PTS.
- Номер правила выбирается только из кандидатов; ссылка и цитата подставляются из проверенного корпуса.
- Валидатор проверяет EOS, JSON, полноту условий, идентификаторы доказательств, UNKNOWN и исключающие условия.
- Сохранены исходные ответы. Код не может доказать смысловую корректность ссылки модели на факт; эту ошибку выявляет сравнительная проверка.
- Модуль не импортируется рабочим gateway. Новые внешние AI API и модели не используются.

## Реальный тест Qwen3-VL-4B-Instruct

Тест на существующей RTX 4090, локальные веса, без обучения. Это **шесть синтетических текстовых ситуаций**, не проверка распознавания видео и не оценка точности на датасете.

Первый вариант: 6/6 завершённых JSON, 5 ответов отклонены за неполный список условий, один ответ без подходящего основания. 16.35 с генерации, 18.06 с вместе с загрузкой, peak allocated VRAM 9153.5 MiB.

Критическая ошибка: в ситуации с присутствующим клиентом модель пометила условие его отсутствия TRUE, хотя в собственном объяснении написала о присутствии. Для непрозрачной сумки сделала необоснованный вывод о невыполненной проверке. Синтаксически валидный JSON этого не предотвращает.

Второй ограниченный вариант: отдельный вопрос на каждое условие. Завершены 3/6 ситуаций; все получили INSUFFICIENT_EVIDENCE. У положительного примера модель сочла исключение «клиент вне поля зрения» истинным несмотря на явное описание проверенного ухода. Здесь требуется уточнить смысл исключения в базе: неизвестное положение человека и подтверждённый уход — разные обстоятельства.

Второй прогон остановлен при достижении установленного лимита памяти процесса (0.39 GPU, примерно 9.22 GiB); свободно оставалось 2.08 GiB. Это не доказательство невозможности запуска на 24 GB: одновременно работал production. Лимит не увеличивался, автоматического перебора не было. Исходный API не останавливался.

Артефакты:

- `docs/evaluations/regulatory-search-20261018.json` — первый полный тест.
- `docs/evaluations/regulatory-search-split-partial-20261018.json` — три завершённых случая второго теста.
- `docs/evaluations/regulatory-search-split-failure-20261018.json` — причина остановки.

## Проверки и дальнейший допуск

22 backend-теста и 7 frontend-тестов прошли; frontend собирается. В интерфейсе добавлена цитата рядом с официальной ссылкой, дата обозначает фактическую сверку. Изменения детекторов, весов, таймкодов и вердиктов не выполнялись.

До включения подбора Qwen необходимы: устранение двусмысленностей машинных условий; успешные положительные и отрицательные контроли, включая присутствие клиента за стеклом; затем проверка на реальных наблюдениях видеопайплайна. Пользователю не предлагается заново проверять статьи вручную. Текущий тест показывает конкретный технический предел, а не обещание точности.
