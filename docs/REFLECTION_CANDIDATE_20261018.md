## Что мешало X-30

RT-DETR уже находил второго человека. Геометрический фильтр `has_twin` в `forte.scene` удалял его трек как возможное отражение: сравнивались положение, высота и движение, но не внешний вид людей. Следовательно, дополнительное обучение детектора людей не устраняло бы обнаруженную причину пропуска.

В отдельной копии обработчика добавлена проверка подавленных треков установленной **Qwen3-VL-4B-Instruct**, ревизия `ebb281ec70b05090aa6165b016eac8ec08e71b17`. Её веса не обучались. Модель получает одно изображение с двумя подписанными вырезками A/B из одного кадра и сравнивает одежду и внешность. Имя видео, ожидаемый ответ, GT-таймкод и описание пользователя на вход не передаются. Три момента выбираются равномерно из общего участка автоматически построенных треков.

Восстанавливается только отрезок между соседними ответами `different_people`, причём для каждого возможного трека-двойника. `uncertain` и ошибка декодирования не подтверждают различие. Ранний спорный участок не восстанавливается. Затем на отдельной восстановленной сцене выполняются существующие правила присутствия рядом с кассиром; прежние события сохраняются.

На полном наборе такие подавленные пары возникли только в X-19 и X-30:

- X-19: все три ответа — возможное отражение, трек не восстановлен, нового события нет.
- X-30: на 12,444 с модель ответила «возможное отражение», на 15,254 и 18,465 с — «разные люди». Восстановлен только отрезок **15,254–18,465 с**.

Это проверка визуально разных фигур, а не установление личности или полномочий человека. В обосновании полномочия отмечены как неизвестные, нормативная применимость — условная.

## Изменения в ходе разработки

Первая попытка с тремя отдельными изображениями давала путаницу между фигурами и обрезанные ответы. Вход заменён на единую подписанную пару, ответ сокращён, лимит установлен в 192 токена. После просмотра ответов способ восстановления изменён с целого трека на подтверждённый интервал. Эти решения принимались на знакомых сценах X-19/X-30; считать последующий прогон независимым тестом нельзя. Исходные попытки сохранены в отдельных экспериментальных каталогах, результаты не затёрты.

Геометрические пороги исходного фильтра не менялись. Обученная голова папки взята из предыдущего цикла без изменения весов или порога; подробности в [отчёте обучения](PATCH_OBJECT_TRAINING_20261018.md). Содержимое папки визуально неизвестно. X-24 учитывается как положительное видео согласно разметке и предыдущему подтверждению пользователя; прямая нормативная ссылка новому наблюдению не назначена.

## Проверки

- Все 40 запросов передавали исходные видео под нейтральным именем `video.mov` и создавали новые задачи. Сохранённые ответы не использовались вместо inference.
- Исходные события, JPEG и обоснования на всех 40 видео совпали с результатом свежего базового анализа. Сравнение с предыдущим baseline также показало отличия только X-24 и X-30.
- Максимальное время последовательного локального запроса — **25,14 с**. Это не измерение внешней загрузки или параллельной нагрузки.
- Без ключа API возвращал 401.
- Для каждого нового события сохранены три разных JPEG. X-30: **14,733333 / 15,266667 / 15,800000 с**; PTS каждого кадра точно найден в исходнике через ffprobe. Все три изображения просмотрены: две разные фигуры видны, первый кадр даёт контекст до подтверждённого интервала.
- Старые подписи объектов не исправлялись: на X-30 аппарат ошибочно подписан «Сейф». Этот эксперимент проверял людей и не подтверждает правильность остальных рамок.
- Четыре теста прошли: ранний спорный участок не восстанавливается, UNKNOWN не соединяет подтверждения через пробел, каждый возможный двойник проверяется, ошибка декодирования не вызывает модель и не восстанавливает трек. Исправление обработки ошибки декодирования добавлено после полного прогона и отдельно проверено тестом; успешный путь inference не менялся.
- SHA-256 **89 файлов** рабочего backend совпали до/после. Публичный worker `ready`, очередь пуста. Тестовый API остановлен, порт 17071 закрыт.

## Следующий этап

Перенести подтверждённую обработку в самостоятельный production-пайплайн и повторить полный регрессионный прогон перед переключением сайта. Текущий исследовательский обработчик вызывает существующий базовый API по loopback; просто заменить им этот базовый worker нельзя — получится вызов самого себя. Для интеграции следует переиспользовать уже загруженные модели, сохранить исходные события и условные формулировки, а также проверить поведение при ошибках новой ветки. Дальнейшее улучшение X-13/X-34 требует распознавания действий с банкнотами и машиной; этот прогон их не исправил.
